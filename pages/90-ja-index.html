zkfmi.com · 研究スタック · Rust · MIT

読めないものを決済する市場基盤

zkFMI は、決済層が金額も銘柄も当事者も読まずに両脚を同時に動かし、それでも「価値が保存された」「両脚が動いた」「指図は一度だけ使われた」ことを誰でも検証できる、金融市場基盤のプロトコル群です。移転を決めるのは市場でもファンド管理者でも銀行でもよく、判断は一つの証明付き指図に載ります。掲載する数値にはすべて計測 artifact があり、限界はすべて文書に書いてあります。

何をするか: 判断はどこで、指図は一つ、決済は読まずに

移転を決めるのが市場（見積や板）でも、業務システム（ファンド管理者、担保エンジン、銀行の審査）でも、その判断は一つの封印された指図（zkPI）に載ります。決済層（DeFMI）は指図の証明だけを検証して両脚を同時に動かし、何が決まったかは知りません。このサイトで例に使うのは見積依頼（RFQ）で、勝った価格は commitment のまま venue を出て、最小値であることの証明が参照し、定足数が署名し、指図が運び、台帳の積の証明が消費します。一つの値、四つの証明、一度も開かない。 ファンドの申込・解約や担保差入れ、二通貨決済も、指図を出す側が違うだけで同じ経路を通ります。

決済が読まないもの

  • 金額
  • 価格
  • どの銘柄か
  • 誰が誰に払ったか
  • 指図を出した側の判断の中身（例: RFQ なら値付け規則と負けた見積）

隠す仕組み

  • Pedersen commitment と範囲証明
  • 移転ごとに新しい blinded asset tag
  • one-of-many ring を持つ note 台帳
  • 7 ノード Shamir 分散、honest majority、malicious 安全
  • 一つの seed から venue ごとに導出する handle

決済が確かめること

  • 価値が生成も消滅もしていない
  • 残高が負にならない
  • 資金脚 = 数量 × 価格
  • 両脚が動くか、どちらも動かない
  • 一つの指図は一度だけ、3-of-7 の署名付き

構成要素

核は指図（zkPI）と台帳（DeFMI）で、その脇に資格（DeKYX）と清算（DeCCP）。指図を出す側（市場と、ファンド管理者などの業務システム）はその上に載り、入れ替え可能です。QOMM は最初に作った市場で、このサイトの作業例に使っています。

指図

zkPI

ゼロ知識証明付き決済指図。金額・価格・資産の commitment、nullifier、期限、FROST 定足数署名、閾値範囲証明 2 本。wire 上 9,726 バイト。
決済

DeFMI

分散型金融市場基盤。commitment 残高上の DvP/PvP、ring 署名付き note、asset tag、ネッティング、デフォルト・ウォーターフォール、正本台帳との照合。専用の非 EVM Avalanche L1 として動作。
資格

DeKYX

分散型 Know Your X。一つの行為に必要な資格だけを証明する匿名提示。audience・action・nonce・期限に束縛。scope 別 nullifier、署名付き失効一覧、鍵交代。
清算

DeCCP

分散型清算機関。閾値統治の清算簿、gross-gross から net-net、証拠金、秘匿保証枠、決定的な損失ウォーターフォール。DeFMI 受領証があるときだけ状態を進める。
市場

QOMM

問い合わせを見ないマーケットメイキング。16 社の値付け規則を、誰も見ない依頼に MP-SPDZ の中で適用。最良見積を最小値として証明し、開かずに決済。公開値には差分プライバシー。
市場

OCLOB

注文内容を見せない連続指値板。法人側で 7 分割し各ノードへ暗号化配送。5-of-7 委員会が照合前に受付順を確定。MPC 内で価格・時間優先。公開板は価格帯別合計だけ。
業務システム

Aethel

支払ストリームの債権化。署名された支払ストリームを金融可能な債権にし、独立した提供者が審査・保証・資金・サービシングを供給。zkPI を発行して決済。

これは何ではないか

研究実装です。監査を受けていません。資産を保管しません。複数ノードの受入はすべて 1 台の Linux ホスト上のプロセスまたはコンテナで、管理者も一人です（AvalancheGo 検証者 5、MP-SPDZ 7、板ノード 7）。独立した組織、実 WAN、HSM 保管鍵、法的 finality 制度での運用は行っていません。日本の振替制度の下では DeFMI は振替口座簿にはなれず、鏡として照合します。「準拠している」「CCP は不要」「監査可能だから統制がある」はいずれも主張しません。Status に本番までの残課題を項目ごとに列挙しています。

耐量子化の状況

署名と鍵交換をハイブリッドに移行中です。Ed25519 + ML-DSA-65（両方の検証が通ったときだけ受理）、X25519 + ML-KEM-768（全常設接続、古典方式への降格は拒否）。共通基盤 crate zkfmi-crypto を 8 リポジトリすべてが参照し、P1〜P6 の統合ブランチが 2026-09-06 に単一ホスト上のネイティブ受入（市場・finality・lifecycle・P6 復旧、15 分）を通過しました。最終 rev の固定・lock 再生成・ゲート再実行・main への統合が残っており、9 月 7 日の週を目標にしています。ゼロ知識の関係式（Pedersen、範囲証明、ring、quote proof、FROST）は意図的に古典のまま、性能比較・WAN・HSM・FIPS・外部監査は未実施です。詳細は Post-quantum migration（英語）。

他のシステムとの比較

Canton、Renegade、Arcium、Zama、Corda、Kinexys、Fnality、Partior、Ownera、Swift、Chainlink、Progmat、ibet for Fin、Prime Match、Penumbra、Dusk、Aztec、Fabric の 18 件を、各社の仕様書・発表・監督当局資料から 2026-09-05 に読み比べました。順位表ではありません。差を述べられる軸、相手が先を行っている軸、その結果としてこの計画が言ってよい文と言わない文を整理したものです。最重要の比較対象は Canton です。必要な当事者だけが平文を読む方式（自社バリデータとアプリ運営者は読める）と、計算するノード自身にも完全な注文を渡さない方式との違いが、示せる可能性のある差です。予約と原子的な DvP は Canton の Token Standard が既に標準化しており、それ自体は差になりません。日本では JGB 担保・レポの実証が Canton 上で 3 件進んでおり、同じ業務の置き換えは提案せず、その中で計算主体にも隠す必要のある部分（注文、レート提示、担保配分）に焦点を絞る方針です。「世界初の金融 MPC」「唯一」「競合より速い」「全系統が耐量子」は使いません。詳細は Comparison with other systems（英語）。

この研究の進め方

数値は手で書かない

掲載する数値はすべて artifact（JSON）と、それを書いた Rust バイナリを持ちます。DeFMI や監査の文書は JSON から生成し、散文の数字が計測から乖離しないようにしています。

予測を先に書き、外れを残す

各計測文書は「予測・実測・外れた方向」の表で終わります。設計変更の多くは外れた予測から来ました。net-net が 1/8 になる予測は 1.62× で外れ、その結果としてサイクル単位の attestation が生まれました。

主張の撤回を公開する

初期稿の主張のうち 3 件を、帰属すべき論文名とともに撤回一覧に載せています。「MPC を公開検証可能にした」は Baum–Damgård–Orlandi 2014 のものです。

fail closed、TEE は信頼境界の外

MPC が欠けたら平文計算へ落とさず止まります。検証できない検証器は「受理」ではなく「構文が通った」と言います。CPU 製造者の attestation を信頼境界に加えません。

よくある質問（要約）

トークンはありますか

ありません。販売も投資対象もありません。MIT ライセンスの研究コードです。ノードが差し入れる bond の額は運用側の決定で、コードは相対的な重みしか持ちません。

ブロックチェーンですか

決済層は専用の非 EVM Avalanche L1（AvalancheGo が Rust VM を起動）として動きます。市場（QOMM、OCLOB）はチェーン上ではなく 7 ノードの秘密計算で、指図を発行するだけです。DeKYX、DeCCP、Aethel は決定的状態機械です。

なぜ EVM や Solana ではないのですか

検証器の算術が収まらないからです。EVM バイトコードでの ed25519 スカラー乗算は 302,401 gas。Solana は曲線の syscall はあるがスカラー体の syscall がなく、one-of-many 検証は crowd 64 で計算上限を超えます。

規制当局や監査人は何を見られますか

三つの粒度の選択的開示が実装済みです。一つの committed フィールドだけ開く、ウォレットの一つの scope（銘柄・四半期・mandate）だけを名指しの監査人に渡す、定足数が誰も保持しない合計について組み立てる照合証明。実際の監督者の鍵儀式や法的要請の手続きは未接続です。

本番に何が必要ですか

単一主体が開けない決済権限、算術上でなく実際に独立した運営者、認証付き記憶域での状態世代の永続化、認証・鍵管理、validator が検証できる秘密計算全体の証明、法的 finality。それぞれ現状と併記して Status に列挙しています。
