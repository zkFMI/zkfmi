耐量子化への移行

移行はハイブリッドかつ fail-closed である。資金を守る古典的な署名と鍵交換のすべてに耐量子の相方を付け、両方の検証が通ったときだけ受理し、古典方式しか提示しない相手は拒否する。作業は 8 リポジトリすべての統合ブランチ上にあり、2026-09-06 に単一ホスト上のネイティブ受入を通過し、零関係の開封証明の修正を取り込んだ 2026-09-07 にも再び通過した。4 リポジトリ（zkfmi-crypto、zkPI、DeKYX、DeCCP）は受入済みの状態が main に入っている。DeFMI、QOMM、OCLOB、Aethel は、DeFMI と QOMM の間の依存の循環が解けるまでブランチに留まる。

基盤: zkfmi-crypto

他のすべてのリポジトリが git rev を固定して依存する一つの crate。語彙と組み合わせ方を定めるもので、各サービス自身の鍵保管や DeKYX の発行者 epoch を置き換えるのではなく、それらに共通の形を与える。

  • スイート識別子。閉じていて版付き。使用中の古典スイート（Ed25519、ristretto255 上の FROST、ristretto255 上の Pedersen と Bulletproofs、TLS 1.3 の X25519、SHA-256/512、SHAKE128）、耐量子スイート（ML-KEM-768、ML-DSA-65、ML-DSA-44、SLH-DSA-SHA2-128s）、ハイブリッド（X25519MLKEM768、Ed25519+ML-DSA-65）。それぞれが用途とバイト長を持ち、テストで FIPS 203/204/205 の定数と照合する。未知のスイートや版は拒否し、既定値に落とすことはない。
  • 正規化した署名入力。プロトコル、版、ネットワーク、配置、契約、トランザクション種別、オブジェクト識別子、シーケンスまたは nonce、期限、スイート、本文ハッシュを、固定幅整数の長さ接頭辞付きでドメイン ZKFMI:CANONICAL:v1 の下に並べる。golden バイトベクタは hex で固定してある。同じ本文でも用途が違えば前像が変わるので、署名を別の用途へ流用できない。
  • 用途に束縛した鍵。鍵レコードは参加者、用途（見積、決済指図、鍵の交代、統治、トランスポート、attestation）、スイート、世代、有効期間、失効、交代の証明を名指しする。交代は双方向に署名する。旧鍵が新鍵に署名し、新鍵が旧鍵の識別子に署名する。
  • ハイブリッド署名。同じ正規化入力に対する Ed25519 と ML-DSA-65。両方の検証が通ったときだけ受理し、片方の失敗、片方の欠落、二つの入れ替わりはいずれも拒否する。ML-DSA のコンテキスト文字列は用途とスイートを含む。
  • ハイブリッド鍵交換。独立に生成した秘密による X25519 と ML-KEM-768 を、両方の共有秘密、両方の暗号文、スイート識別子にわたる HKDF-SHA256 で結合する。どちらの半分を差し替えても導出鍵が変わることをテストで確かめている。
  • バックエンド。RustCrypto の ml-dsa 0.1.1 と ml-kem 0.3.2（純 Rust、Apache-2.0 OR MIT）をバイト指向のトレイトの背後に置き、aws-lc-rs のような FIPS 認証済みバックエンドに後で差し替えられるようにしてある。古典側は ed25519-dalek 2.2 と x25519-dalek 2.0。#![forbid(unsafe_code)]、秘密は zeroize する。この選択は工学上の選択であり、本番・監査・FIPS の主張ではない。

バイト数はどれだけ増えるか

方式公開鍵署名または暗号文
ML-KEM-7681,184 B (dk 2,400 B)1,088 B
ML-DSA-441,312 B2,420 B
ML-DSA-65（採用）1,952 B3,309 B
ML-DSA-872,592 B4,627 B
SLH-DSA-SHA2-128s32 B7,856 B

3-of-7 の承認に必要な ML-DSA-65 署名 3 本で 9,927 B になる。古典スタックで計測した決済パッケージの大きさ（口座レールの実行で 57,971 B、64 ビットのレールでの Bulletproofs で 3,424 B）に対して、追加の署名は支配的な項ではない。ただし計画にある暫定の目標 16 KB と上限 32 KB は、すでにそれを超えるパッケージ定義を前提に書かれたものであり、定義を確定した後に再設定する。ポリシー更新の経路では ML-DSA-65 は Ed25519 の約 15× のバイト数で、実際のマーケットメイカーが使う頻度でも毎秒 3 メガバイト未満である。比較を計測するまで、このサイトでは耐量子の所要時間を主張しない。

ネイティブ受入で動かしたもの

8 リポジトリすべての凍結したソーススナップショット 1 つ（1,119 ファイル、実行の前後でハッシュが一致）を Linux ホスト 1 台で固定イメージにビルドし、そこから、ハイブリッド TLS アダプタ上の 7 つの MP-SPDZ プロセス、DeFMI の L1、OCLOB のメイカー API とテイカー API を動かした。4 つのシナリオが順に通り、合計 15 分。

  • 市場: 3 ラウンド、自律決済 2 件、耐量子の応答署名 4 本、一回限りの鍵 8 本、応答を失った後の復旧、重複決済ゼロ。
  • finality: 署名付きの秘匿状態の受領証が、同じプロセス内の再試行、再オープン後、別プロセスからのいずれでもバイト単位で同一に返る。二重適用は拒否。7 ノードの正規化された観測。差し替えは拒否。ウォレットの再オープン。請求 3 件。秘匿保証枠の witness 2 件を復旧し、次の注文で消費。
  • lifecycle: 約定 3 件、新しい耐量子鍵 12 本、応答署名 6 本、部分約定後の順序付き取消（厳密なリプレイと再起動を含む）、期限切れによる解放、7 ノードの再起動チェックポイント。
  • P6 復旧: 新たに解決した不変な依存関係の下での復旧テスト 2 件。

この実行で 2 件の欠陥が見つかり、通過前に修正した。再試行ごとに ML-DSA 署名を再生成していた受領証（署名済みの受領証を永続化して再送するようにした）と、部分約定後に新しい操作識別子で再認可されていた返金の開封値（元の請求コンテキストを保持するようにした）。ブランチ上の補助ゲート: OCLOB のテスト 125 件、zkPI・DeKYX・DeCCP・P5 ワークスペースにわたる 279 テスト、QOMM のトランスポートとデモのテスト、Aethel のエンドツーエンド、すべて strict clippy 付き。

古典のまま残るもの、その理由

この移行が扱うのは署名と鍵交換である。決済層が依拠するゼロ知識の関係式は扱わないし、まだ扱えない。Pedersen commitment、Bulletproofs の範囲証明、one-of-many ring、quote proof、指図への FROST 閾値署名はいずれも離散対数に立っている。束縛のページに議論の全体がある。秘匿（hiding）は無条件で量子敵にも耐えるが、束縛（binding）は耐えない。ポリシーの有効期間中すべての見積に対して開かれるメイカーのポリシー commitment が、それが最初に効いてくる場所である。VOLE-in-the-Head の commitment は実装して計測した（広い体上で Pedersen の 5.9× から 11×、かつ一回限り）。格子 commitment は Shamir の再構成を壊す。未解決の問いは、ランダムオラクルだけに依拠して何度でも開ける commitment のままである。それが存在するまで、このスタックの耐量子保証は、誰が署名したか、誰がチャネルを読めるかについてのものであり、証明についてのものではない。

他にも二つの小さな点がブランチ上で古典のまま残る。FROST の自己署名は追加した耐量子鍵を覆っていない（ノード別の ML-DSA 承認は FROST の内側ではなく隣に置いてある）。また、コンセンサスの外にある閲覧の許可と支出の開示は移行していない。

根拠の限界

  • ホスト 1 台、管理者 1 人。独立した運営者、WAN、物理 HSM はない。
  • バックエンドの FIPS 認証も外部監査もない。
  • 性能比較はまだない。計画の処理量と遅延の目標（基準値の ≥95%、p95 のオーバーヘッド目標 5 ms）は未計測で、7 プロセスのネットワーク障害テストは 7 ノード WAN の根拠ではない。
  • リリース rev の固定は一部完了。4 リポジトリは受入済みの状態で main にある。DeFMI、QOMM、OCLOB、Aethel は、DeFMI ⇄ QOMM の依存の循環を不変の git rev として表せないため統合ブランチに残る。ブランチは一つのルートの下の隣接した checkout としてビルドし、リモートのゲートもそのように動く。
  • P5 の証明器は本家の alpha 版（Miden 0.32）に依存し、意図的に狭い命題を証明する。
