今後の計画

現状文書、用途調査、ポジションペーパーの未解決の問いから順に並べた。日付はない。約束した日付が一つもないからである。項目は、いつ起きうるかではなく何に依存するかで分けてある。

完了し、受入済みのもの

  • Rust によるプロトコル中核、計測済み

    閾値範囲証明と固定テストベクタを持つ zkPI v2。DeFMI の口座、note、tag、ネッティング、限度、ウォーターフォール、PvP、照合、scope 付き閲覧、審査証明（vetting）。Bulletproof バックエンド。DeKYX、DeCCP、Aethel の crate ワークスペース。

  • 検証者 5 台のネイティブ Avalanche L1、ホスト 1 台

    複数 RFQ の原子的決済、リプレイ拒否、再起動復旧、状態ルートの合意。QOMM 経路は 7 つの MP-SPDZ プロセスから追加の署名なしで決済する。

  • OCLOB から L1 への分散経路、ホスト 1 台

    参加者側での分割、7 コンテナへの暗号化直接配送、5-of-7 の到着証明書、MPC 照合、メイカー予約とテイカー予約、再起動とリプレイの検査付き DvP。

  • 束縛と説明責任の仕組み

    通信量 2.00× の一致体（matched field）。健全な参加者ごとの入力検査。誤った share の位置を特定するデコーダをエンジンに組み込み。n=9 の頑健な再構成を 2 台の計算機で計測。

  • 記録に残る 2 回のレビュー

    健全性の指摘は修正し文書化した。撤回した主張は一覧にした。外れた予測は残した。

次にやること、依存関係の順に

  • 耐量子化の統合を main に載せる

    8 リポジトリすべてにわたる Ed25519 + ML-DSA-65 のハイブリッド署名と X25519 + ML-KEM-768 の鍵交換が、統合ブランチ上で 2026-09-06 に単一ホストのネイティブ受入を通過した。2026-09-07 には零関係の開封証明の修正を取り込んで再び通過した。同日にスタック側の crate を zkPI へ移して DeFMI ⇄ QOMM の循環を断ち、各リポジトリを不変の rev で固定し、8 つすべてが main にある。残りは、計画が求める性能上のオーバーヘッドを計測する。耐量子化への移行を参照。

  • OCLOB の決済権限の閾値化

    参加者の固定長の決済権限を開く単一の研究用ゲートウェイを、MPC ノードによる閾値復号か zkPI の共同生成に置き換える。OCLOB を実資産から遠ざけている P0 項目。

  • OCLOB 向けの L1 上の note レール

    QOMM の L1 受入は口座レコードをゼロにして動く。OCLOB の正本状態はまだ commitment 口座と予約ルートを使っている。

  • 受付・差入れ・限度・支払の原子化

    付与と受付は別々の呼び出しで、差し入れた担保をロックする状態はない。要件として書いてあるが、実装していない。

  • 状態世代の永続化

    暗号化キュー、レート制限のカウンタ、nullifier 台帳を認証付き記憶域に置き、再起動をまたいで保つ。ロールバックがリプレイを再び可能にすることも、2 プロセスで動かした市場が許容量をすべて二重に持つこともなくすため。

  • 本番運用に必要な周辺

    mTLS、テナント別の認可、OpenAPI、レート制限、監査ログ、外部 KMS/HSM、鍵の交代、バックアップと復旧。現状はデモ用 API のみ。

  • ノード間のオフライン段階

    オンライン段階は trusted dealer ありでバイト数の 16% と計測済み。7 ノード間の実際の前処理プロトコルは実装していない。

  • 差分プライバシー開示のバイアス補正

    DP 開示は、非線形な統計量の上方バイアスのため、開示なしより悪い結果を計測した。MPC 内のサンプラーには、純粋な DP を主張する前に、厳密で上限を設けない構成が必要。

  • 遅い委員会向けの参照価格の補正

    勝者は参照価格に依存せず、価格は参照価格のアフィン関数である。それでも実装は計算と同じだけ古い価格を明かす。

業務システム、用途調査が勧める順に

  • 1. ファンドの申込と解約

    発行者、管理者、投資家、KYC で別々の鍵。資格、上限、予約、発行可能な口数を一つの zkPI に束縛。資金 note と口数 note を一緒に更新。超過申込、期限切れ、リプレイ、片脚のテスト。

  • 2. 担保と証拠金

    資格、ヘアカット、集中度を承認済みの回路として。秘密のポートフォリオに対するカバー率の証明。差替えと返還。主体ごとの上限の下での同時呼び出しの順序付け。最も強い研究テーマ。

  • 3. 二通貨 PvP

    一つの指図に 2 発行者と 2 予約。障害、期限切れ、再起動、再送のテスト。ISO 20022 は外部アダプタで。

  • 4. 外部台帳との接続

    ファンド、担保、銀行の模擬台帳を独立プロセスとして。署名付きの予約と受領証。どの障害が原子性を壊すかの明示的な一覧。

コードの外にあるものに阻まれているもの

  • WAN 上の独立した運営者

    7 つの MPC 運営者、5 以上の検証者、別々の管理者、鍵保管、障害ドメイン。残る最大の未知で、リスク登録簿が最も難しいと言うもの。

  • 秘密計算の証明

    検証者は提出されたものすべてを検証するが、MP-SPDZ のトランスクリプトを再実行することも、share から証明への引き渡しを証明することもしない。これを閉じるには MPC 全体の証明とコンセンサスのベンチマークが必要。

  • 法的 finality と振替口座簿への接続

    振替口座簿、CSD、中央銀行または指定された資金脚、監督者の開示ワークフロー。EU と英国では自然な置き場所は非株式の RFQ で、スイスでは台帳の記載が権利そのものになりうる。

  • 独立した監査

    第三者による、暗号、Rust 状態機械、ホスト VM、統合の監査。内部レビュー 2 回はそれではない。

未解決の研究課題

  1. ランダムオラクルだけに依拠して何度でも開ける、公開検証可能で線形同型な F_p 上の commitment。
  2. 群の位数も収まる体での、7 者 Shamir 向けのスラックのない比較。
  3. 公開の説明責任に対する honest majority の代価。
  4. 通信の漏れと選択的停止を含む、OCLOB の形式的な安全性定義と証明。
  5. Prime Match の 2 ラウンドの malicious 比較が 7 者 Shamir に移せるか。
