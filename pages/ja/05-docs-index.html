ドキュメント一覧

これらのページは、7 つのリポジトリにある設計文書、レビュー記録、計測 artifact から抜き出したものである。市場基盤を作る、あるいは評価する立場で、何が証明され、何が計測され、何がまだ主張にとどまるかを正確に知りたい読者に向けて書いている。

読み方

  1. 全体構成が骨格を示す。誰が判断し、誰が指図し、誰が決済し、どの秘密がどこにあるか。
  2. zkPI と DeFMI がプロトコルの核である。二つは併せて読む。指図は、それを消費する台帳がなければ意味を持たない。
  3. QOMM と OCLOB がこれまでに作った二つの市場である。市場以外の業務システムは、二つが製品ではなく例であることを論じる。
  4. 束縛、監査、説明責任、配置は、MPC の計測の大半を行った RFQ 市場を深く掘る。これらは QOMM についてのものであり、決済層はこれらに依存しない。
  5. 安全性、計測値、現状が根拠のページである。一つだけ読むなら現状を読む。何が受入済みで何がそうでないかが書いてある。この研究の進め方は、根拠のページがなぜこの形をしているかを説明する。

このサイトの約束事

  • 数値はすべて artifact 由来である。計測値にはホストのラベル（host-a、host-b、host-c）と、それを収めた artifacts/ 配下の JSON ファイルを示す。機械の較正値はその数値の脇に書く。他の何かを比べる前に、まず較正値を比べる。
  • 「実装済み」と「受入済み」は別の語である。実装済みとは、コードが存在しテストが通ることである。受入済みとは、リポジトリのリリースゲートで実行されたことである。どちらも本番を意味しない。
  • 「主張しない」は脚注ではなく一つの節である。各プロトコルのページは、それがしないことで終わる。その一覧はレビュー記録から来ており、仕組みと同じだけ設計の一部である。
