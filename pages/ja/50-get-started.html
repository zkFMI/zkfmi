始め方

すべて Rust で、lock ファイルはリポジトリに含めてある。ライブラリのテストは Rust が動く場所ならどこでも走る。ネットワーク系の受入ゲートには Linux と、明示的に用意した AvalancheGo が必要で、MPC を通る経路には公式の MP-SPDZ の checkout も要る。スクリプトが外部バイナリを勝手にダウンロードすることはない。

clone してテストする

git clone https://github.com/zkFMI/defmi.git
cd defmi/rust
cargo test -j 4 --locked --workspace

同じコマンドが zkpi と qomm でも使える。単体の crate は四つのゲートを順に通す形になる。

git clone https://github.com/zkFMI/dekyx.git   # or deccp, aethel
cd dekyx
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all -- --check
cargo build --workspace --release --locked

rust-toolchain.toml は置いていない。評価を始めるときに rustc --version を記録し、ビルドに使う機械の間で同じ版に固定すること。統合用の Docker ビルドは現在 Rust 1.97.1 を参照している。

指図のテストベクタを検査する

qomm-zkpi-verify --check-vectors artifacts/zkpi_vectors
qomm-zkpi-verify --self-test

終了コード 0 は受理、1 は拒否、2 は判定に至らなかったことを表す。受理されるベクタは、復号して再符号化したときに同じバイト列に戻らなければならない。--vectors <dir> でベクタを作り直すのは形式が変わったときだけで、検査結果が食い違ったからという理由で作り直してはならない。

検証者 5 台の L1 ゲートを走らせる

defmi/ から、承認済みの版の AvalancheGo と avalanche-network-runner を用意した上で実行する。

cargo build --release --manifest-path rust/Cargo.toml -p qomm-avalanche-vm -p qomm-harness
# launchers and configuration under avalanche/defmivm/
cargo run --release --manifest-path rust/Cargo.toml -p qomm-harness --bin run_avalanche_l1_acceptance

実行すると artifacts/avalanche_l1_acceptance.json が書き出される。企業向け PoC ガイド（日本語）は、ソースの固定、VM のビルド、ネットワークの起動、取引シナリオ、追加の署名なしで通る QOMM 経路、必須の拒否試験と障害試験、保存すべき証拠、合格条件を順に案内し、その先の企業による評価に向けて、ハードウェアの見積、プロセス分離、ネットワーク設計、genesis、鍵管理、バックアップ、監視、障害注入まで続く。

QOMM の座席デモを試す

cd qomm
cargo run -j 4 --release --manifest-path rust/Cargo.toml -p qomm-harness --bin serve_demo
# then hand out seats:
#   http://<host>:8800/?seat=taker
#   http://<host>:8800/?seat=maker:1&label=Ann
#   http://<host>:8800/?seat=node:3&label=Rin
#   http://<host>:8800/?seat=observer

各ブラウザには、その役割が見るはずのものだけが送られる。observer の座席はすべてを表示し、どの配備にも存在しない眺めであることを毎フレーム明示する。

OCLOB のゲートを走らせる

OCLOB のビルドとテストはリモートホスト上の Linux コンテナの中でだけ行う。Makefile がソースをそこへ送る。

make release-gate REMOTE_TEST_HOST=<linux-host> REMOTE_TEST_REUSE_IMAGE=0
make remote-distributed-e2e REMOTE_TEST_HOST=<linux-host>
make remote-integrated-e2e  REMOTE_TEST_HOST=<linux-host>

結果は artifacts/oclob_rough_e2e.json、oclob_distributed_e2e.json、oclob_distributed_avalanche_acceptance.json に書き出され、それぞれが自身の non_claims と privacy_boundary のフィールドを持つ。

文書を artifact から作り直す

cd defmi
make defmi-doc      # DEFMI.md from artifacts/*.json; no number typed by hand
cd ../qomm
make audit-doc      # AUDIT.md likewise

企業向け PoC ガイド

  • DeFMI: 導入、役割分離、障害事例、証拠、受入、そして 41 節の運用指針。
  • QOMM、DeKYX、DeCCP、Aethel、OCLOB。

いずれも日本語。合成資産、使い捨ての鍵、インターネットに出さないネットワークを前提とし、後から監査人が言葉を信じるのではなく実行そのものを検査できるよう、どの証拠を残すべきかを述べている。
