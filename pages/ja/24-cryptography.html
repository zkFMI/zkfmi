暗号技術の使い方

各部品のページは、その部品が何を保証するかを述べる。このページはそれをどう実現しているかを述べる。どの群、どの生成元、どのトランスクリプト・ラベルを使い、検証器がどの等式を検査し、wire 上を何バイトが渡るか、という水準でである。ここにあるものはすべて 2026-09-07 にコードから読み取り、ファイル名を挙げてある。コードと古い設計文書が食い違うところではコードの側を報告し、食い違いを末尾に一覧にした。

群、生成元、ハッシュ

すべての commitment、証明、古典署名は ristretto255、すなわち Curve25519 上の素数位数群の中にあり、4.1.3 に固定した curve25519-dalek を通して扱う。下限はワークスペースのマニフェストに明記されている。4.1.3 には、コンパイラがスカラー減算に持ち込んだタイミング漏れ（RUSTSEC-2024-0344）の修正が入っており、dalek 系は 2019 年に Bulletproofs crate と併せて Quarkslab の監査を受けている。生の曲線ではなく Ristretto を選んだ理由はコードに記録されている。以前の版は点へハッシュしながら余因子を消しておらず、よく知られたライブラリが受け入れる符号化の 39% は素数位数でなかった。Ristretto には間違えようのある余因子がない。

二つの Pedersen 生成元は、このスタックが選んだものではない。Bulletproofs crate から取っており、g = B（Ristretto の基点）と h = hash-to-group(SHA3-512, B) である。これは意図的である。範囲証明はその crate が選ぶ生成元の下で commit し、決済はその commitment を、台帳が自分で作った commitment と比較する。二つの生成元の組が違っていれば、どの等式も型検査は通り、両者の間のどの束縛も空虚になる。範囲証明と決して出会わない用途のために、SHA-512 で導出した独立な第二の生成元対がある。

資産ごとの生成元、すなわち asset tag は、固定ラベルと資産識別子の hash-to-group である。

A_a = hash_to_group(SHA-512, "qomm:defmi:asset:" || be32(asset_id))

資産 a の残高は A_a の下で、g の代わりとして commit され、h は変わらないので、h についてだけ語る証明は値の生成元を替えても有効なままである。同じ hash-to-group の型が、審査名簿のおとりの席（ラベル qomm:defmi:vetting:decoy:v1。運営者を含め誰もおとりの開封値を持たないようにするため）、or-DLEQ 証明の scope 生成元、そして note の証明で資格のない ring メンバーの代わりに置く点（DEFMI:NOTE:INELIGIBLE:v2）を作る。

チャレンジは決して手作りのハッシュではない。すべてのシグマ・プロトコルは Merlin トランスクリプト（Keccak-f[1600] 上の STROBE）の上で動く。点はラベルの下に圧縮形で追記され、チャレンジは 64 バイトをスカラーに還元したものである。したがって三つのハッシュ族が、それぞれ一つの役割で現れる。Merlin は証明のチャレンジ、SHA-512 は hash-to-group と鍵導出、SHA-256 はダイジェストと wire 上の識別子である。

commitment と保存則

commitment は加法記法で C = g·v + h·r、あるいは H·q + h·r である。後者は盲化した asset tag H = A_a + h·γ の下での形である。口座台帳上の保存則は証明も開封もなしに、状態全体にわたる一つの等式で検査する。

Σ accounts + Σ escrowed(pending PvP legs) == minted

escrow（決済待ちの預かり）は明示的に数える。これを外すと、prepare された脚はすべて価値の消滅に見え、commit はすべて価値の生成に見える。振替ごとに、台帳は準同型性を直接強制し、その後に範囲証明を一つ求める。

balance − amount_commitment == remainder_commitment      // arithmetic, no proof
remainder_commitment ∈ [0, 2^bits)                        // Bulletproof

この一組が「負にならず、生成されない」の全部である。asset tag の下では、盲化因子（blinding）の帳簿付けだけが唯一の細かい点で、支払側の残りの盲化因子は r_payer − r_amount − γ·balance になる。H^(v−q) h^t が balance / amount に着地しなければならず、それに γ·v がかかるからである。ネッティングのレールも、残高の代わりにポジションを置いた同じ形をしている。

六つのシグマ・プロトコル

zk crate は独自のシグマ・プロトコルを実装している。この用途の既存の crate は、本番用ではないと自ら述べているか、監査を受けていないかのどちらかだからである。各プロトコルは Merlin 上で非対話にした三手の証明で、形は第一手の点を commit し、追記し、チャレンジを取り、z = k + c·witness で応答する、である。圧縮した点とスカラーはそれぞれ 32 バイトである。

DvP の決済では、このうち三つを一緒に検査する。証券脚が指図の commit された数量を動かすことを示す生成元をまたぐ証明が一つ、price × amount が commit された現金の参照値に等しいことを示す積の証明が一つ、資金脚がその参照値を動かすことを示す生成元をまたぐ証明が一つである。これらは一つのバッチに積まれ、単位元に対する一回のマルチスカラー乗算で決着する。そのバッチの隣には、健全性の規則が二つコードに書かれている。バッチの重みは検証器が引き、トランスクリプトからは決して取らない。トランスクリプト由来の重みは証明者も計算できるものであり、そうなると集約した一つの関係を解けてしまうからである。そしてバッチ化しない検証器は、積の証明の二つの半分を別々に検査しなければならない。和にした検査は一度 2 × 3 = 8 という証明を受け入れたことがあり、それを偽造するテストが crate に残されている。

範囲証明。本番は Bulletproofs、基準線はビット

本番経路上の範囲証明はすべて Bulletproof（bulletproofs 5.0.0）で、幅は 8、16、32、64 ビット、2 の冪で集約して値 0 の詰め物で埋め、幅を超える値は crate が拒否しないので証明の前に拒否する。単一の 64 ビット証明は 672 バイトで、七つの要素に、2·log₂(n·m) 個の点と二つのスカラーからなる内積論証を加えたものである。検証はマルチスカラー乗算一回で、決済パッケージが幅でほとんど動かない（64 ビットで 3,424 B）のも、「決済」時間が 7.02 ms なのもそのためである。

ビット分解による構成は、切り替え可能なバックエンドではなく、計測済みの基準線として残してある。各ビットをリトルエンディアンで新しい盲化因子の下に commit し、各ビットをそれ自身の副トランスクリプトの下でビット証明によって証明し、重み付き和を元の commitment に連結し直す。C − Σ 2^j·C_j は h の純粋な倍数でなければならない。費用はビットあたり 192 バイト（ビットの commitment に 32、その証明に 160）に連結を加えたもので、パッケージの残りを数えると wire 上で 896 B/bit、検証に 0.80 ms/bit である。本番の呼び出し元は、図の「線形バックエンド」の行を作る計測ハーネスだけである。

しかしその閾値形は本番経路上にある。定足数が、どのメンバーも保持していない値について範囲を証明するとき、ビットごとの OR 証明はシェアからは作れない。そこで閾値範囲証明はビットの commitment と連結を残し、OR を体の等式 b·b = b に置き換えて、これを共同で証明する。閾値 DvP パッケージが二つの予約の残量に使うのがこれで、zkPI が二つの閾値範囲証明として運ぶのもこれである。有界区間は幅 ⌈log₂(high − low)⌉ の範囲証明二つで、検証器は内側の幅も検査する。これが防ぐ攻撃はコードに書かれている。区間 [−4000, 4000] と値 4001 に対して、value − low は 8001 で 13 ビットでは正直だが、high − value は −1、すなわち ℓ − 1 であり、253 ビットでは正直である。

one-of-many。tag と審査証明には Groth–Kohlweiss、note には Triptych

Groth–Kohlweiss 証明は、集合の中の一つの commitment が、どれかを言わずに 0 に開くことを示す。実装は基数 2 に固定されている。集合の大きさは 2 の冪でなければならず、m = log₂ N で、証明者は自分の添字のビット（cl_j）、ランダムなマスク（ca_j）、その積（cb_j）に commit し、m 個の多項式係数の点 G_k = Σ_i p_i[k]·C_i + h·ρ_k を公開し、チャレンジに f_j、za_j、zb_j と一つの集約 zd で答える。証明サイズはちょうど 32·(7m + 1) バイトなので、大きさ 16 の集合は 928 B、倍にするごとに 224 B 増える。検証は倍にするごとに 2× ではなく約 1.4× で伸びる。バッチ化したマルチスカラー乗算が透けて見えており、これが既定の審査証明の群を 16 から 128 に動かした予測の外れである。

用途は二か所である。口座の発行時に、盲化した tag H が登録済みの資産生成元の一つであることを、商 H − A_i（登録された添字でちょうど h·γ に等しい）の上で示す。資産レジストリは 2 の冪に詰めてあり、資産が上場されるたびに増える集合が上場を漏らさないようにしてある。証明の費用は決済ごとではなく口座ごとに一度である。もう一つは以下の審査証明である。

note の ring はもう Groth–Kohlweiss ではない。note レールのバージョン 2 は Tari の Triptych を改作している。これは並列の one-of-many 証明で、同じ ring の添字を使い捨ての所有者鍵と値の commitment の両方に束縛し、連結不能な linking tag を生む。パラメータは基数 2、指数 max(2, log₂ ring)、ring の上限 4,096、証明の上限 1,800 バイトで、正規符号化は復号時に再検査する。ライブラリはコミットで固定し、その注意書きをアダプタでも繰り返している。元のライブラリの実装は実験的であり、これは監査の主張ではない。

note、serial、nullifier

アドレスは対 (A, B) = (g·a, g·b)、閲覧鍵 a と支出鍵 b で、ウォレットの側で分けてあるので、閲覧鍵は note を見つけられるが支出はできない。拒否するためのメソッドは存在せず、スカラーが単にそこにないだけである。支払側は一時的な e を引き、E = g·e を公開し、note の使い捨ての点 g·H(A·e) + B を作る。受取側は共有スカラーを閲覧鍵から、serial を支出鍵から再計算する。

shared = H_512("qomm:defmi:note:v1:" || "shared" || E·a)
S      = shared + b
masks  = H_512(… "mask:value" …), H_512(… "mask:blinding" …)

値と盲化因子はこの二つのスカラーでマスクして運ばれるので、走査は note あたり Diffie–Hellman 一回とハッシュ二回である（0.05 ms）。note は g·S の点と値の commitment A_a·v + h·r を別々に公開する。一つの点に畳んでしまうと、決済が証明を突き合わせる相手がなくなるからである。note の識別子は DEFMI:NOTE:BODY:v2 の下での本体全体の SHA-256 で、和ではなくハッシュにしたのは、まさに悪意ある受取人がその分解を変えられないようにするためである。

支出時に公開されるのは Triptych の linking tag U·S⁻¹ で、U はライブラリの第三の生成元である。g·S もスカラーも決して公開しない。これは 2025 年 9 月の note 証明レビューでの欠陥 N2 だった。検索可能な使い捨て鍵を公開していれば、支出が支払いと結び付いていたはずである。支出の証明が運ぶのは、tag、入力値への再盲化した疑似 commitment、Triptych の ring 証明、出力の commitment と note の束縛、出力にわたる集約 Bulletproof 一つ、そして零開封証明、すなわち pseudo − Σ outputs が h の純粋な倍数であることの証明である（欠陥 N3 はここが一般の開封証明だったことで、0 に固定した変種は今では 0 でない値の応答をすべて拒否する）。二重支出の検査は圧縮した tag への集合挿入で、使用済みの note はプールに残る。取り除けばどれが使われたかを言ってしまうからである。プールの状態ルートは走行 SHA-256 で、追記ごとと支出ごとに一度延長する。プールを歩き直す方式が、約 8 ms の暗号処理に対して決済の 61 ms を占めると計測された後の変更である。

おとりの選び方には実装が二つある。ring_for はプール全体から一様に引き、固定シードのシャッフルで本物の note が常に先頭にならないようにする。ring_recent は最新の note から引く。決済は直前に受け取った note で支払うものであり、一様に選んだおとりはたいてい最新ではないからである。計測した攻撃がその差を示している。ring 16 で、他の通信として決済 16 件があるとき、名目 0.062 に対して 0.359 である。今日ハーネスとテストに配線されているのは一様な規則だけで、新しさの規則はベンチマークの中に存在し、台帳自身の状態注記もそう述べている。

PvP のための adaptor signature

状態を共有しない二つの台帳の上の二つの脚は、ristretto255 上の Schnorr adaptor signature で結ばれる。

pre-sign   R = g·r,   c = H(R + Y, X, m),   s' = r + c·x        → (R, s')
verify     g·s' == R + c·X
adapt      s = s' + y                                          → (R + Y, s)
extract    y = s − s'

設計の理由はモジュールに書かれている。ハッシュロックは前像を漏らし、それは両方の台帳に平文で現れて、両方を読む者に二つの脚を結び付けさせる。adaptor が漏らすのはスカラーで、それも事前署名の保持者にだけである。どちらの台帳に着地するのも通常の Schnorr 署名で、nonce の点が Y だけ違い、Y は決して現れない。プロトコルは、提案側と応答側がそれぞれ escrow した脚を用意して事前署名を交換するもので、最初の claim が署名を公開し、二番目の当事者がそこから y を取り出して他方の脚を claim する。escrow は解放鍵を prepare の時点で記録し、期限後の commit を拒否する。unwind に署名は要らず、期限がすべての権限である。脚の名前は台帳の生涯にわたって使い切りになる。安全条件は二つの期限と、気づいて反応するまでの時間との間の不等式であり、反応は 0.06 ms なので、露出の窓は二つの台帳の finality によって決まり、このコードの中の何によっても決まらない。

登録簿との照合、96 バイト

commitment は準同型なので、口座の残高 commitment の和は、和への commitment である。

Σ C_i = A_a·(Σ v_i) + h·(Σ r_i)
residual = Σ C_i − A_a·N          // N is the register's figure

登録簿が正しければ残差は h の純粋な倍数であり、それを示す 96 バイトの証明は、合計が一致することを言い、それ以外は何も言わない。登録簿の数字、口座、資産、基準日はチャレンジにハッシュされるので、証明を別の attestation に対して再生することはできない。attestation 自体は登録簿の管理者が ed25519 で署名する。集約した盲化因子を誰かが持つ必要はなく、3-of-7 の定足数が応答を組み立てられる。不一致の場所を特定するには開示という代価がかかり、それは設計である。二分探索は 2·log₂ n + 1 個の副証明を作り、公開した範囲をすべて報告する。

所見、2026-09-07 に確認し同日修正。その日まで、ここの検証器は残差の一般の開封証明を検査しており、それが示すのは、何らかの (v, r) について residual = g·v + h·r が成り立つと知っていることだった。開封値を持つ者は、どんな N に対してもそのような証明を持つ。このページを準備しながら書いたテストは、合計 6,000 の残高に対して合計 6,500 の照合を受け入れさせた。二つ目のテストは、同じ形をしていたビット分解の連結を再証明することで、300 への commitment を 8 ビットの範囲証明に通した。同じ型は、zkPI と閾値 DvP パッケージが運ぶ閾値範囲証明の連結、quote proof の「勝者が公開値に開く」段、規則監査の等価の段にもあった。5 か所すべてが、note 支出が既に使っていた 0 に固定した開封証明を使うようになり、閾値の組み立てではどのノードの nonce も値の成分を持たないので、組み立てた応答の値の部分は命題が成り立つときにちょうど 0 になる。二つの偽造は、crate の 3 つのコピーすべてで回帰テストになっている。詳細は決済リポジトリの所見注記にある。

scope 付き閲覧

scope の区切りは鍵ではなくアドレスにある。ウォレットは 32 バイトのシードを二つ持ち、scope（銘柄、四半期、委任）ごとに次を導出する。

view_s  = H_512("qomm:defmi:view:v1" : "view"  : seed_v : scope)    // the auditor gets this
spend_s = H_512("qomm:defmi:view:v1" : "spend" : seed_s : scope)    // it does not
address = (g·view_s, g·spend_s)

閲覧の付与は、付与先、アドレス、閲覧鍵、有効期間を名指しし、ed25519 で署名される。その検査では、署名と、鍵が名指しされたアドレスを開くことと、日付を確かめる。監査人はその鍵で note を走査し（使い捨ての点と値の commitment の両方が再構成できてはじめて、その note はウォレットのものと認められる）、値と盲化因子を受け取るが serial は受け取らず、上の照合を scope にわたって走らせることができる。三つの限界は隠さずに明記されている。付与は取り消せず、取り消しとはアドレスの交代である。閲覧鍵が見るのは入ってくる価値だけである。serial がアドレスに属するのは S − H(E·a) = b のときにちょうど限られ、そのハッシュがこれをシグマ・プロトコルで証明できる範囲の外に置くからである。そして scope の区切りは、支払側が現在のアドレスを使うことに依存する。したがって出金は署名付きの開示、検証ではなく帰属であり、コードは同じ scope について閲覧鍵と serial を組み合わせることを拒否する。その組み合わせはウォレットそのものだからである。

審査証明（vetting）。一つの handle、一つの席、128 の群

審査名簿は封印された封筒 C_i = a_i·G + r_i·h を保持する。handle A が審査を通ったことを示すには、保持者は、ある C_i − A が 0 への commitment であることを one-of-many で証明する。そのグループは handle の生涯にわたって固定されているので、ring を交差させることはできない。さらに、A = a·G が基点だけの冪であることの Schnorr 証明を付ける。この後半が荷を負っている。one-of-many 証明だけでは C_ℓ − A が h の倍数であることしか言わず、A + δ·h はどんな δ についてもそれを満たす。A を基点に固定することが、法人ごとの上限にとって「一つの審査に一つの handle」を意味あるものにする。おとりの席は誰も開けない点へハッシュしてあるので、名簿の審査済みメンバー数は正直である。席はランダムに割り当てるので、位置が加入の順序を符号化しない。グループの型は crate の外では構成できないので、検証器は名簿のダイジェストをチェーンが公開したものと比べなければならない。群 128 の検証は 3.80 ms、1,676 バイトである。16 では所属証明は 1,004 バイトで、うち 928 が ring、64 が制御の証明、12 がグループとエポックである。数千の中に隠れるには、回路の中で検査する Merkle 木が要り、それはこのスタックが基づくものとは別の証明系である。

ネッティング、日中限度、ウォーターフォール

net のレールは証明を一切使わずに累積する。差分一つ、支払側一つ、受取側一つ、position_payer −= Δ、position_payee += Δ であり、意図的に借方・貸方の組にしていないので、保存則は忘れられ得る検査ではなく構成によって成り立つ。gross のレールでは注文ごとにカバーの証明が必要で、net のレールではそれは拒否される。締めの時点で、各 handle は充足を一度証明する。

headroom = position + limit                          // both commitments
Bulletproof(headroom ∈ [0, 2^bits)) under transcript "qomm:cycle:close" || rail || handle

検証器は主張 position_commitment + cap_commitment を教えられるのではなく再構成し、他のどの点についての証明も拒否する。上限は commitment として入り、その盲化因子はポジションの盲化因子に加えられるので、証明は position + cap についてのもので、ポジションが 0 のどちら側にあったかを決して明かさない。符号付きのポジションを隠すのに本来必要になるオフセットの技法は、どこにも要らない。余裕（headroom）の算術は 128 ビット整数で行う。リリースビルドでは桁あふれが黙って起き、あふれた余裕は、充足していないポジションが充足しているという証明になるからである。

限度の付与は collateral·(10,000 − haircut_bp) − cap·10,000 ≥ 0 を、拡大した余剰に対する範囲証明として証明するので、整数除算を証明する必要が決して生じない。幅は拡大率の分の 14 ビットだけ増え、注文ごとではなく付与時に一度払う。デフォルト・ウォーターフォールは積の証明の連鎖で、draw_k × remaining_{k−1} = 0 の積の commitment を単位元に固定する。後のトランシェは前のトランシェが尽きたときにだけ引き出せる。attestation 付きサイクルは取引ごとの検証を省き、代わりに、サイクル識別子を長さ接頭辞として付けたダイジェストに対する定足数の ed25519 署名を要求する。ある静かなサイクルの attestation が、次の静かなサイクルを一度決済してしまったからである。計測した結果は DeFMI のページにある。取引 64 件、参加者 8 で、gross-gross 400 ms、net-net 247.5 ms、attestation 付き 20.6 ms である。

       || "QOMM:QUOTE-PROOF-DIGEST:v1" || quote_proof_digest )

範囲の証拠は意図的に署名対象のダイジェストの外にある。市場は範囲を別に検証してから署名を検証し、domain がレールをまたぐ再生を止める。鍵は認証付きコーディネータ上の三ラウンド FROST DKG から来る。コーディネータは署名付きの身元、公開のブロードキャスト、受信者向けに暗号化した第二ラウンドのパッケージだけを中継するので、誰も群の秘密を保持しない。trusted dealer のコンストラクタは存在するが、配備ではなく fixture（テスト用の固定部品）と札が付いている。署名は標準の二ラウンド、使い捨ての nonce commitment の後に部分署名で、64 バイトに集約する。群の鍵だけを受け取る検証器は、同じ点に集約する別の定足数と区別できないので、市場は完全な公開鍵パッケージを保持する。業務システムが使う型付き zkPI は、操作、scope、方向、市場と台帳の識別子、三つの handle、予約識別子と連番、RFQ の nullifier、委任と受領証のダイジェスト、直前の状態ルートに対する第二の FROST 署名を加える。両方の署名が検証を通らなければならない。

handle は参加者ごとに 32 バイトのシード一つ、市場ごとにスカラー一つで、s_V = H_512("QOMM:ZKPI:HANDLE:v1" || seed || len(venue) || venue)、H_V = g·s_V である。乗法的な代案 g·(a·h(V)) は却下され、その却下はテストになっている。H_A·h(B) = H_B·h(A) が成り立つのは二つの handle が一つの法人に属するときにちょうど限られるので公開で連結可能であり、計測では、観察者が市場をまたぐ交換の二つの脚を確実に結び付けられた。ドメインをまたぐ DvP は一つの指図を異なるダイジェストで二つの台帳に射影するので、二つの公開記録は取引識別子を共有しない。本文は、二つの異なる台帳配備、送り元とも送り先とも異なる escrow、arm < claim < refund の期限を要求する。

検証器の終了コードは、0 が受入、1 が拒否、2 が問い合わせ不能である。定足数の鍵と時計がなければ配置だけを検査し、そのことを言葉で言う。整形式で未署名の指図に「ok」と印字する道具は、無いより悪いからである。受け入れたテストベクタは復号して再符号化すると同じバイト列にならなければならず、これは「解釈できた」より強い主張である。

閾値証明。シグマの応答は affine なのでシェアが結合できる

定足数が、どのメンバーも保持していない値についての証明を作れる理由は、一行の代数である。シグマの応答は z = k + c·w で witness について affine なので、各ノードは自分の Shamir シェアから z_i = k_i + c·w_i を計算し、その断片は群のスカラー体の中で Lagrange 結合して z になる。これが成り立つのはシェアが群のスカラー体に住むときだけで、それが下の一致体（matched field）である。ビットごとの範囲証明は OR 構成を使えない。ビットから分岐を選ぶことは affine でないからである。閾値形は代わりに b·b = b を積の関係として証明し、その応答は affine である。

プロトコルは commit、reveal、チャレンジ、応答で、commitment を先に封印する。各ノードは reveal の前に、自分の nonce の点の SHA-256 封印を QOMM:THRESHOLD-RANGE:ROUND1:v1 の下で公開するので、適応的なノードが正直な nonce を打ち消すことはできない。reveal は封印と正確に一致し、定足数も正確に一致し、コンテキストのダイジェストも一致しなければならない。各ノードが持つのは自分の値のシェア、盲化因子のシェア、ビットごとの三つ組と、公開の VSS 係数 commitment だけで、使う前に自分のシェアを公開の VSS の主張と照らして検査する。公開の主張は指数の中でだけ再構成され、その関数はスカラーのシェアも範囲の値も受け付けない。検証は通常の公開検証器で、シェアも定足数もセットアップも入力に取らない。市場はさらに、数学的には有効な単独証明者の Bulletproof の証拠を、出所の方針として拒否できる。単独の証明者は平文の再構成点になっていたはずだからである。

であり、これはちょうど ristretto255 の位数である。これが一致体（matched field）で、仮定ではなく強制されている。証明の組立器は回路の素数を群の位数と照らして検査し、回路はある幅の体で書かれ、commitment は 253 ビットの体に住んでいる、という文言で拒否する。回路の一行の変更は Σ LAGRANGE[p]·input_p を Σ input_p の代わりに置くことで、公開値と秘密値の積は局所計算なので、ラウンドも入力数も変わらない。代価は通信量がちょうど 2.00× で、要素が 16 バイトから 32 バイトに増える分だけであって他には何もなく、壁時計時間は 1.06 から 1.07× である。計測記録は自身の誤りも残している。最初の版はラウンド 2.02×、通信量 14.3× と報告し、その差の全部はコンパイル・フラグ一つで、その警告をフレームワークは毎回の実行で印字していた。

盲化因子は MPC の中で引く。生成された回路は価格の盲化因子とすべてのビットの盲化因子に sint.get_random() を呼ぶので、どの当事者も r を知らない。勝者は、各メイカーの決済価格に最良キーとの等価フラグを掛けることで、見ないまま（obliviously）選ばれる。各ノードの永続化ファイルは自分の Shamir 評価値だけを受け取る。各ノードは次に Com(share_i, blinding_i) を公開し、公開 commitment C = g·price + h·r は指数の中で Lagrange 補間によって再構成される。後段の発行者が平文の見積から何かを作り直すよう求められることはなく、閾値範囲から指図を組み立てるコンストラクタは API 上、開封値を受け付けないので、発行者プロセスが隠れた再構成点になることを防いでいる。

quote proof は Baum–Damgård–Orlandi の公開監査可能 MPC を実体化したものである。入力提供者は Pedersen commitment を公開し、オンライン段階は監査人が commitment 上で再実行できる線形演算である。メイカーごとに次を証明する。

depth_i = slope_i × qty                 product proof
skew_i  = invcoef_i × inv_i             product proof
ask_i   = level_i + depth_i + skew_i    linear, free
bid_i   = level_i − spread_i − depth_i + skew_i
fits_i  = maxqty_i − qty ≥ 0            range proof
fresh_i = expiry_i − now ≥ 0            range proof
ok_i    is a bit and gates the cost
key_i   = cost_i × M + i                linear, free

そして集合全体について、勝者の commitment が公開値に開くこと、key_i − v ≥ 0 がすべての i について成り立つことを証明する。最小性と所属を合わせればちょうど「v は最小値である」なので、誤った勝者は証明できない。六つの偽造制御（最小でない勝者、期限切れのメイカー、約定できない依頼、切られた勝者、入れ替えた最小性証明、偽の勝者に対する最小性）が拒否として記録されている。登録済みの値付け規則の盲化因子を持たない witness は拒否されるので、最小値は証明者が捏造した commitment ではなく登録済みの commitment の上で取られる。各メイカーの二つの資格範囲は一つの集約 Bulletproof を共有し、最小性の範囲も同様である。host-a で 7 ノードの計測では、メイカー 4 で証明 62 ms、検証 19 ms、メイカー 16 で 246 ms と 71 ms である。3 者の定足数による共同組立は 4.8 ms で、どのノードも witness を持たず、通常の検証器がその結果を受け入れる。

計算したものを commit したものに束縛する。ノードは配られたシェアを配る側の commitment と照らして検査できる。だがその後 MPC に入れる値がそのシェアであることは、何によっても強制されない。健全な参加者ごとの入力検査がこれを閉じる。回路はシェアを読みながら保存し、全入力が入ったところで一つのランダムな ρ を開き、Σ ρ^k·share_k を commitment の同じ結合と照らして検査する。健全性は Schwartz–Zippel により m/p で、253 ビットの体に 166 個の値で約 2⁻²⁴⁵、旧来の狭い体で 6 ビット係数を七回繰り返した 2⁻⁴² を置き換える。費用はラウンド 1 回の追加と通信量 0.39% の増加である。配る側は比較ではなく同一性で束縛する。値に commit する参加者がそれをシェアに分ける参加者であり、参加者ファイルを書く一回のパスで行う。commit していないものを配った側は、何かが計算される前に、最初の不一致の位置で捕まる。

嘘をついた者を名指しする。次数 t の秘密の Shamir シェアは Reed–Solomon 符号語 RS[n, t+1] なので、Berlekamp–Welch は ⌊(n − t − 1)/2⌋ 個までの誤ったシェアを訂正し、その根が嘘をついた参加者の評価点である誤り位置多項式を返す。n = 7、t = 2 では、新しいシェア分散で容量 2、次数 2t の積では 1 であり、n ≥ 4t + 1 はここから来て、頑健な構成が 9 ノードである理由もこれである。計測では、容量までは 300 回中 300 回で犯人を正確に名指しし、容量を超えると 300 回中 0 回で、シェアの通信量は 40% 増、追加ラウンドはない。フレームワーク自体は検出しかしない。その整合性の失敗は参加者の情報を運ばず、1 バイトを反転させた四回の実行は、二つの異なる犯人に同じ文字列を返した。検出した障害は Ed25519 署名の受領証（QOMM:AUDIT:v1、ノードごとスロットごとに一つ）と、固定の表を持つ bond の台帳に流れる。食い違う二重の発言（equivocation）1,000,000、分岐した状態と省かれたメイカー 500,000、古い状態と不正な署名 250,000、受領証の欠落 50,000、相対単位である。説明責任のページに五段からなる説明責任の段階がある。配備中のエンジンは第 1 段である。

差分プライバシー。公開される件数は MPC の中でサンプリングしたノイズを載せる。秘密シェアされた 64 個のランダムビットが一様な 64 ビットの u をなし、切り詰めた両側幾何分布の量子化した CDF と比較して、越えた閾値の数から台（support）の大きさを引いたものがノイズである。この機構は純粋 DP ではなく (ε, δ) である。台が有限で、折り返した裾により隣接する入力の台が感度の分だけずれるからである。δ は閉形式ではなく e^ε でのホッケースティック・ダイバージェンスとして計算する。閉形式は過小に見積もるからである。ε = 0.5、台 8 で、計測した公開は δ ≈ 2.1 × 10⁻⁴、28 ラウンド、7 者にわたって 63.9 MB で、ノイズがラウンドの 93% を占める。純粋 DP を主張する前には正確な非有界サンプラーがなお必要であり、より安価な可分な構成は知られているが実装していない。

転送。入力のシェアは固定長 495 バイトのフレーム（QOMMWIRE v4、体の要素 14 個）で運ばれ、実行体 ℓ の中で引く。以前の版は 2²⁵⁵ − 19 の上でシェアを分け、テストでは正しく再構成できたが、フレームワークが自身のスカラー体で還元すると別の値を出した。ノードや勝者への封筒は、受取人の鍵への X25519 で封筒ごとに新しい一時鍵を使い、共有秘密に対する HMAC-SHA-256 の extract-and-expand で一時鍵と見積のダイジェストを info に入れ、ヘッダを関連データとする ChaCha20-Poly1305 である。ノード間のサービス通信は相互認証 TLS である。これは P0 の結合器であり、ハンドシェイク・プロトコルではない。何がこれを置き換えるかは耐量子のページが扱う。

OCLOB。シェアは参加者の手元で作り、到着は 5 台が証明する

法人参加者は、どのコーディネータも注文を見る前に、六つのフィールド（売買の向き、指値、数量、有効期間、期限、GTC フラグ）の次数 2 の Shamir シェアを作る。秘匿性のある Pedersen VSS commitment を付けるので、各ノードは小さな価格や数量を知ることなく不整合なシェアを拒否でき、また commitment は裸の g·price のように総当たりでは破れない。各シェアは一つのノードに封じる。固定 8,192 バイトの平文、新しい X25519 一時鍵、導出した封筒鍵、封筒ヘッダを関連データとする ChaCha20-Poly1305 で、相互 TLS の上で直接届ける。コーディネータは注文の内容を受け取らない。

受付の順序は照合の前に到着証明書で固定される。7 ノード中 5 台が、Ed25519 で、次の同一の文に署名する。

SHA-256( "OCLOB:ORDER-VOTE:v1" || len(market) || market || sequence
       || order_commitment || previous_certificate || expires_at )

一つの連番で異なる文に二度投票したノードは、食い違う二重の発言（equivocation）である。証明書には、同一の文のダイジェストを持つ少なくとも 5 台の異なるノードと、厳密な署名検証が要る。ログは各証明書が先行するものを名指しすることを要求するので、連鎖は正規であり、繰り返された commitment は再生である。方針の定数は凍結されている。7 ノード、腐敗し得るのは 2、再構成の定足数 3、順序付けの定足数 5 で、検証器は他のどの形も、腐敗の上限の二倍を超えない順序付け定足数も拒否する。照合は ℓ 上の同じ malicious Shamir MPC の中の価格・時間優先で、約定ごとに 7 ノードは、616 本の秘密シェアされた証明用ワイヤから、数量と価格の範囲、数量 × 価格、そして現金、証券、メイカー予約の残量が非負であることを共同で証明する。

注文の決済権限は、注文ごとの鍵で封じた固定 65,536 バイトの封筒で、その鍵は 3-of-7 で Feldman シェアされている。参加者が署名し VSS で検証済みのノードの解放のうち任意の三つからの再構成は、スカラーを補間してから公開 commitment と照らして検査し、二つのシェアでは常に失敗する。開く側は平文バッファをゼロ化し、復元した注文をマニフェストと照らして再検査する。ノードは、有効な MPC 結果を永続化した後、決済専用の相互 TLS 接続の上でだけ自分のシェアを解放し、解放が許されるのは、その結果が注文の約定または残量付きの到着を示したときだけである。照合前の単一の復号鍵は存在しない。P0 項目として残るのは旧来のブラウザデモで、そのコーディネータはシェアに分ける前の平文の注文をまだ見る。ネイティブ経路は見ない。

DeKYX。Ed25519 署名付きの commitment、Schnorr の提示、scope nullifier

クレデンシャルは BBS+ でも CL でもない。Pedersen で commit した主体の秘密、属性の Merkle ルート、scope とポリシーのダイジェスト、エポックと有効期間からなる SHA-256 ダイジェスト（DEKYX:CREDENTIAL:v1）に対する、発行者の Ed25519 署名である。主体の commitment は g·s + H_b·r で、H_b = hash-to-group("DEKYX:SUBJECT-BLINDING-GENERATOR:v1") である。保持者が s を生成し、発行時に開封値の Okamoto 証明で所持を証明する。発行者が見るのは commitment と証明だけで、どちらのスカラーも見ない。属性は Merkle の葉なので、選択的開示とはポリシーが要求する葉とその経路を明かすことである。

提示は、一つのチャレンジの下での二基点 Schnorr AND 証明である。

g·z_s + H_b·z_r  == A_c + c·commitment
H_scope·z_s       == A_n + c·nullifier          where H_scope = hash-to-group("DEKYX:SCOPE-NULLIFIER-GENERATOR:v1" || scope)
c = H_512("DEKYX:ANONYMOUS-PRESENTATION:v1" || credential || context || nullifier || A_c || A_n || disclosed leaves and paths)

これにより、署名された commitment の開封値を知っていること、公開された nullifier が H_scope·s であり、その秘密が同じものであること、そしてチャレンジを通して、開示した葉が署名されたルートの下にあることを証明する。コンテキスト（scope、提示先、操作、依頼のダイジェスト、nonce、期限）はチャレンジに入っているので、ある操作のトランスクリプトを別の操作に移すことはできない。消費済みの（nullifier、コンテキスト）の組の台帳は認証付きの記憶装置に置かなければならない。ロールバックが再生を再び可能にするからである。nullifier N_scope = H_scope·s は決定的で、一つの scope の中では連結可能、scope をまたいでは基点が異なるので連結不能である。安定した subject line は発行者、scope、ポリシー、nullifier の SHA-256 で、発行者の鍵交代を越えて生き残るので、業務システムは主体が誰かを知らずに、主体ごとに一つの line や一つの限度を強制できる。

失効リストは DEKYX:STATUS-LIST:v1 の下で Ed25519 署名され、整列済みで厳密に増加し、発行者鍵のエポックに束縛され、その期間の中でだけ有効である。リストが無いか古ければ閉じる側に失敗し、古いリストが新しいものを置き換えることはできない。鍵交代は厳密に大きいエポックを登録し、以前のエポックを猶予時刻で区切る。明記された限界は DeKYX のページにあり、ここでも繰り返す。この方式は scope 内で仮名であって、発行者に対して連結不能ではない。署名された commitment は一つのクレデンシャルの中で安定しており、発行の記録と相関させ得るからである。発行者に対する連結不能性には、レビューを受けた BBS+ や CL のアダプタのような、再ランダム化可能なクレデンシャルが要る。

耐量子ハイブリッド

基盤 crate は ed25519-dalek 2.2.0、ml-dsa 0.1.1、ml-kem 0.3.2、x25519-dalek 2.0.1 を正確に固定し、提供元のコミットと tarball のハッシュを記録し、二つの格子系 crate は独立の監査を受けていないという提供元の声明を繰り返している。

署名、Ed25519 + ML-DSA-65。ハイブリッド署名は単純な連結 ed25519(64) || ml_dsa_65(3309) で 3,373 バイト、公開鍵は 32 + 1952 である。復号は正確な長さだけを受け付ける。両成分はハイブリッド・スイートの中で生成され、両方が検証を通らなければならず、格子側の誤りが古典のみの受入に変換されることは決してない。共有コンテキストは "ZKFMI:SIGNATURE:v1" || purpose(u16) || suite(4) である。ML-DSA はこれを FIPS 204 のコンテキストとして受け取り、ランダム化して署名する。コンテキスト入力を持たない Ed25519 は、別のドメイン "ZKFMI:ED25519-CONTEXT:v1" || len(context) || context || len(message) || message に署名し、厳密に検証される。スイート識別子は安定した wire 上の判別子で、宣言順から推測することは決してない。ハイブリッドは 0x202 である。

鍵交換、X25519 + ML-KEM-768。結合器は次のとおりである。

HKDF-SHA256( salt = "ZKFMI:HYBRID-KEM:v1",
             ikm  = ss_x25519(32) || ss_mlkem(32) || ct_x25519(32) || ct_mlkem(1088) || suite(4),
             info = "ZKFMI:HYBRID-KEM:SESSION:v1",  L = 32 )

公開鍵は 1,216 バイト、暗号文は 1,120 で、暗号文の古典側の半分は送信者の一時 X25519 鍵である。寄与のない X25519 の結果は両側で拒否し、秘密はゼロ化し、古典のみの代替経路はなく、ML-KEM の暗黙の拒否により、改竄された暗号文は誤りではなく別の秘密を生む。これは P0 の結合器である。相手を認証せず、ハンドシェイクではない。

正規化した前像 ZKFMI:CANONICAL:v1 は、署名が何に対するものかを固定する。プロトコル名とバージョン、ネットワーク、配備と契約の識別子、用途コード、オブジェクト識別子の一覧、連番または nonce、排他的な期限、スイート、32 バイトの本文ハッシュで、すべて長さ接頭辞付きのビッグエンディアン、Unicode 正規化も整列もしない。本文の符号化はプロトコル自身のもので、入る前に SHA-256 でハッシュする。鍵の記録は参加者、用途、スイート、単調増加する鍵バージョン、有効期間と失効の時刻を持つ。交代は双方向に署名される。旧鍵が ZKFMI:KEY-ROTATION:AUTHORIZE:v1 に、新鍵が ACKNOWLEDGE に署名し、それぞれ両方の束縛を覆う。参加者や用途の変更、世代の飛び越し、鍵の再利用、ハイブリッドから古典へのロールバックは拒否される。

ハイブリッドが古典のまま残すものはスイート表自体に明記されている。FROST の定足数署名、Pedersen commitment、Bulletproofs、古典 TLS の転送は post_quantum = false を持つ。このフラグはアルゴリズムを分類するもので、実装を保証するものではない。シグマ層を単純に格子へ差し替えられない理由についての市場側自身の分析は、三つの障害を挙げる。大きさ（シグマの一段あたり 4,960 バイトに対して、数キロバイトから数十キロバイト）、棄却サンプリング（abort の判定が結合した応答に対して行われるので、棄却はそれが防ぐはずの漏れの後に届く）、そして構造的なもの、すなわち短さが Shamir を越えて生き残らないこと。Lagrange 結合した応答は、短いものに大きな係数を掛けて還元したものだからである。計算自体は既に情報理論的に秘匿されている。量子攻撃者が破るのは commitment の束縛であり、署名と KEM のハイブリッドの統合状況は耐量子のページにある。

何が古典で、何が監査済みで、何を主張しないか

  • すべての commitment、範囲証明、one-of-many 証明、adaptor signature、定足数署名は、ristretto255 の離散対数に依っている。Pedersen commitment の束縛は計算量的にしか成り立たず、メイカーの値付け規則の commitment は規則の生涯にわたって置かれたままである。ポジション・ペーパーはこれを、ここで耐量子の方向を採る最も強い論拠として挙げている。量子計算機は要らず、時間だけで足りる。
  • 耐量子のページのハイブリッドは署名と鍵交換を覆う。離散対数を破る攻撃者に対して Pedersen commitment を束縛にはせず、ゼロ知識の関係は決定として古典のまま残る。
  • 監査済みの部品。curve25519-dalek と bulletproofs（Quarkslab 2019）、frost-ristretto255（NCC Group 2023、部分的、v0.6.0）。未監査。シグマ・プロトコル、Groth–Kohlweiss の実装、Triptych アダプタとその元のライブラリ、note レール、ネッティングと与信の証明、閾値構成、そしてすべてのホスト。二回の内部レビューは先行研究と安全性のページに記録されているが、監査ではない。
  • ここにあるものは何も MPC を証明しない。検証者は提出されたものを検証する。シェアから証明への引き渡しは束縛されているが証明されてはおらず、束縛のページがその費用を計測している。
